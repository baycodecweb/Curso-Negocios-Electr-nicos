Implementado: Sesión 3 sobre Sesión 2 — Resultado esperado

Esta carpeta no es un archivo nuevo de estudio: es una copia del proyecto real de Grafiluz con la Sesión 1 (catálogo) y la Sesión 2 (Puente Digital) ya integradas, a la que ahora se le suma el código de la Sesión 3, para mostrar qué se espera que el alumno logre al adaptar las tres sesiones a su propio proyecto.

Qué se combinó

OrigenArchivoRol
Sesión 1index.html, script.js, styles.cssEl sitio real de Grafiluz (catálogo, carruseles, botón de WhatsApp)
Sesión 2productos-data.js, puente-digital.jsModelado del catálogo y conexión a la API externa de tipo de cambio
Sesión 3db-modelo.jsModelo relacional: Cliente, Pedido, DetallePedido y Pago, guardados en localStorage como si fueran tablas de una base de datos

Qué cambió respecto al index.html integrado en la Sesión 2

  1. Se agregó un enlace en el menú: "MI PEDIDO 🧾".
  2. Se agregó una nueva sección <section id="mi-pedido"> justo después de "Precios Referenciales Internacionales" (Sesión 2) y antes de la sección de clientes, con el formulario de registro de cliente (B2B/B2C), el carrito de productos y el resultado del pedido.
  3. Se agregó el <script> de db-modelo.js al final del body, después de puente-digital.js, junto con un pequeño script inline que conecta el formulario con crearCliente() y crearPedido().
  4. Se agregaron los estilos .pedido-section, .pedido-form, .pedido-campo, .pedido-carrito, .pedido-item y .pedido-resultado al final de styles.css, usando los mismos colores de marca de Grafiluz (rojo #C41F25 y azul #1A1C72) ya usados en la Sesión 2.

Nada de lo construido en la Sesión 1 ni en la Sesión 2 fue eliminado: la integración es puramente aditiva.

Qué hace realmente el modelo de datos aquí

Al llenar el formulario y presionar "Generar pedido":

  1. crearCliente() inserta una fila en la tabla clientes (con tipo: "B2B" o "B2C").
  2. crearPedido() inserta una fila en pedidos, una fila por cada producto elegido en detallePedido, y una fila en pagos con estado: "Pendiente".
  3. Se muestra el número de pedido y el total, y un botón para confirmar por WhatsApp (el cobro en línea real, con webhook, se conecta recién en la Sesión 7).

Puedes inspeccionar las tablas generadas abriendo la consola del navegador y ejecutando JSON.parse(localStorage.getItem('grafiluz-s3-bd-relacional')), o usando el panel visual de Codigo/demo-modelo-datos.html (carpeta padre).

Por qué este es el resultado esperado, y no solo la demo aislada

Codigo/demo-modelo-datos.html (carpeta padre) demuestra el modelo relacional de forma aislada, con el diagrama DER, para enseñarlo en clase. Esta carpeta muestra cómo ese mismo modelo se integra dentro de un negocio real que ya tenía su catálogo (Sesión 1) y su Puente Digital (Sesión 2), sin romper nada de lo que ya funcionaba. Ese es el nivel de trabajo que se espera de cada alumno: no solo entender el código de ejemplo, sino incorporarlo a su propio proyecto de forma coherente con el resto del sitio.

Cómo probarlo

Como esta carpeta también incluye el Puente Digital (que usa fetch), hay que servirla por HTTP:

cd Implementado-Sesion-03-en-Sesion-02
python3 -m http.server 8000

Luego abrir http://localhost:8000/index.html, navegar a "MI PEDIDO 🧾" en el menú, registrar un cliente (prueba con B2B y con B2C) y generar un pedido con uno o más productos.

Nota: el catálogo de esta carpeta sigue siendo el catálogo de ejemplo (5 productos) definido en la Sesión 2, no el catálogo completo real de Grafiluz — el objetivo aquí es mostrar el patrón de modelado e integración de datos, no reescribir todo el catálogo.
