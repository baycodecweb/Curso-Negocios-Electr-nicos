Anatomía del CRUD

Cuatro archivos, cada uno con una sola responsabilidad, que juntos cubren las cuatro operaciones clásicas sobre datos: Crear, Leer, Actualizar y Borrar (CRUD).

Por qué funciona así

Cada operación vive en su propio archivo y, al terminar, redirige de vuelta a index.php — así esa página siempre refleja el estado real de la base de datos. Los enlaces (Agregar, Editar, Borrar) usan GET porque solo navegan; los formularios que guardan o actualizan usan POST porque modifican datos. El mismo principio de 4-php-formulario, aplicado a cuatro archivos en vez de dos.

línea 2mysqli_connect(...)

Conecta con la base de datos.

línea 3$id = (int) $_GET["id"];

Lee el id de la mascota a editar, desde la URL (?id=5). Esta línea corre siempre, sea GET o POST — porque en ambos casos hace falta saber cuál mascota es.

Actualizar (solo si llega un POST)

líneas 5 y 12if (...) { ... }

Este bloque solo corre si el formulario de edición fue enviado.

líneas 6–8$nombre = $_POST["nombre"]; ...

Lee los 3 campos con los valores nuevos que escribió el usuario.

línea 9mysqli_query(UPDATE ... WHERE id=$id)

Actualiza esa fila específica con los nuevos valores — el WHERE id=$id es lo que evita tocar las demás mascotas.

Redirige a index.php y detiene el script, igual que en crear.php.

Si el script llegó hasta aquí es porque no hubo POST — o sea, es la primera vez que se abre esta página para esa mascota. Trae su fila actual.

Guarda esa fila en $mascota, como un array asociativo.

línea 16?>

Cierra el bloque PHP.

línea 17<form method="post">

Formulario que envía por POST, hacia este mismo archivo (editar.php?id=...), para actualizar.

líneas 18–20<input value="<?php echo $mascota[...]; ?>">

A diferencia de crear.php, cada campo trae un value con los datos actuales de $mascota — por eso el formulario aparece ya lleno, listo para modificar en vez de escribir todo de nuevo.

Borrar y volver

línea 1<?php

Abre el bloque PHP.

línea 2mysqli_connect(...)

Abre su propia conexión, porque este archivo se ejecuta por separado al seguir el enlace "Borrar".

línea 3$id = (int) $_GET["id"];

Lee el id de la URL y lo fuerza a número entero.

línea 4mysqli_query(DELETE ...)

Borra la fila con ese id.

línea 5header("Location: index.php");

Redirige de vuelta a la lista.

Dato relacionado

editar.php es el único de los cuatro que combina lectura y escritura en un mismo archivo — porque necesita leer los datos actuales para mostrarlos en el formulario antes de que el usuario pueda escribirlos de nuevo. crear.php y eliminar.php no lo necesitan: uno solo escribe, el otro solo borra.
